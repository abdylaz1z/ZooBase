# Аудит ZooBase — 11 октября 2026

Основание: исходный репозиторий `abdylaz1z/ZooBase` и предоставленное ТЗ ZooBase 1.0.
Результат этой итерации — улучшенное автономное Android-приложение версии 0.2.0.
Это локальное приложение одного хозяйства. Сервер, SMS-авторизация и совместная работа не реализованы.

## Архитектура

Python/Kivy/KivyMD отвечают за интерфейс, Peewee/SQLite — за данные. В проекте семь таблиц:
хозяйство, владелец, животное, медицинская запись, задача, репродуктивное событие, настройка.
Внешние ключи включены, SQLite работает в WAL. Контроллеры отделены от экранов.
Сохранение медицинской записи вместе с задачей и репродуктивного события вместе с изменением статуса транзакционно.

Новые Android-модули используют системный выбор документов и локальный AlarmManager.
Напоминания читают актуальные задачи напрямую из SQLite, поэтому не требуют работающего Python-процесса или интернета.

## Исправленные проблемы

| Область | Было | Стало |
| --- | --- | --- |
| Родословная | Допускались циклы и родители из другого хозяйства | Проверка всей цепочки предков, хозяйства, пола и возраста |
| Правка родителя | Можно было изменить пол/дату так, что потомство становилось противоречивым | Проверка уже связанных потомков |
| Изоляция записи | Обновление по ID не проверяло хозяйство | Обновление ограничено переданным хозяйством |
| Дата поступления | Поле модели не сохранялось и отсутствовало в форме | Ввод, сохранение, проверка и отображение |
| Медицинские даты | Допускались будущие выполненные мероприятия | Проверка будущей даты и даты рождения |
| Репродукция | Историческое событие могло изменить актуальную беременность | Запрет обратного порядка событий, проверка хозяйства партнёра и выбытия животного |
| Фото Android | Устаревшее разрешение общего доступа к файлам | Storage Access Framework без разрешения на всю галерею |
| Удаление фото | Проверка префикса пути могла затронуть соседний каталог | Проверка реального общего каталога |
| Транзакция фото | Старое фото удалялось до завершения транзакции | Удаление после успешного сохранения |
| Большое стадо | Жёсткое ограничение списка на 300 животных | Порционная выдача по 50 с кнопкой продолжения |
| Поиск | Полная перерисовка при каждом символе | Задержка 250 мс при вводе |
| Дальние задачи | Задачи после семи дней были скрыты | Раздел «Позже» |
| Потомство | Отображалось только число потомков | Ссылки на карточки потомства |
| Сохранность | Переносимых резервных копий не было | ZIP базы и фото, безопасное восстановление, CSV стада |
| Перенос на новый телефон | Не было восстановления при первом запуске | Кнопка восстановления на экране регистрации |
| Обещание синхронизации | Счётчик «ожидает синхронизации» без сервера | Честная информация о локальном хранении |
| Интерфейс | Перекрытие статистики, обрезание переключателя, слабый контраст тёмной темы | Исправленные размеры, горизонтальные фильтры, светлый цвет действий в тёмной теме |
| Android 15 | Системная навигация перекрывала подписи нижних вкладок | Отдельная совместимая тема для API 35 с системными панелями вне SDL-поверхности |
| Сборка | Непроверяемые зависимости и отсутствие тестов | Зафиксированный Buildozer/p4a, тесты логики, проверка экранов и Android-запуска |

## Проверка

Автоматические регрессионные тесты проверяют 500 карточек, повторное открытие базы,
кириллический поиск, уникальность номера/чипа, циклы родословной, даты и пол родителей,
связи между хозяйствами, напоминания, репродукцию, каскадное удаление,
миграцию старой базы, обработку фотографий, ZIP-восстановление и безопасный CSV.

UI-сценарий открывает настоящие экраны Kivy: регистрация → животное → здоровье → задача →
список → хозяйство → кыргызский и тёмная тема. Изображения сохраняются как артефакт CI.
22 регрессионных теста и UI-сценарий прошли. Проверены все 126 используемых ключей перевода.
Android-сценарий успешно установил APK в эмулятор Android 15 (API 35), отключил сеть,
проверил запуск и повторный запуск без Python traceback и Java fatal exception.
Подтверждающий запуск: https://github.com/boboevproject-rgb/ZooBase/actions/runs/38088263280
Цифровая подпись APK v2 проверена Android apksigner. В пакете три ABI: arm64-v8a, armeabi-v7a, x86_64;
minimum API 26, target API 35. Проверка на API 35 не заменяет испытания всех поддерживаемых версий Android.
Сборочный commit: 49c89bc. Старые одноразовые скрипты, перезаписывавшие исходники/CI, отключены.
Полный Android-сценарий также прошёл: без сети созданы хозяйство и животное, ZIP сохранён через
системный DocumentsUI с правильным именем; экспортированная SQLite-база проверена на реальные
значения хозяйства/номера животного. Включение уведомлений создало активное RTC_WAKEUP-расписание.
После принудительной остановки и повторного запуска карточка осталась в базе.
Подтверждение: https://github.com/boboevproject-rgb/ZooBase/actions/runs/38088934820
Фактическое получение уведомления в 08:00 после длительного простоя/перезагрузки отдельно не проверялось.
При будущем переходе target SDK на 36+ нужно заменить опцию совместимости темы полноценной обработкой WindowInsets.
Отдельный физический телефон к рабочему месту не подключён. Семидневный непрерывный полевой тест не проводился.

## Приоритеты следующего этапа

1. Спроектировать и развернуть серверную часть: идентификаторы UUID, журнал изменений и удалений,
   разрешение конфликтов, роли, SMS-провайдер и резервные копии. Поля `synced`/`updated_at` в текущей
   базе недостаточны для надёжной синхронизации; числовые локальные ID нельзя просто отправлять между устройствами.
2. Добавить историю изменения статусов и события отъёма/групп. На их основе строить аналитику за период.
3. Подготовить PDF-паспорт, импорт CSV с предварительной проверкой и массовые операции.
4. Провести пилот с реальными хозяйствами: проверить терминологию на кыргызском, работу камер,
   энергосбережение и уведомления на Samsung/Xiaomi/других целевых телефонах.
5. Подготовить отдельную release-подпись и процесс обновлений перед массовым распространением.
